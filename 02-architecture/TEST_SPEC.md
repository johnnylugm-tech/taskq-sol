## Functional Requirement Test Cases

> Each FR section below follows the **8-Question Protocol** (Q1 happy path,
> Q2 validation/failure, Q3 boundary, Q4 state transition, Q5 fault injection,
> Q6 NFR pattern, Q7 cross-FR integration, Q8 negative constraint). Every case
> has a concrete `Inputs` value in true form (key="value"), NOT the pytest-id
> underscore form. Sub-assertion predicates are valid Python-expression
> syntax; the LHS identifier is never a Python stdlib top-level module or
> builtin name (`json`, `os`, `sys`, `time`, `subprocess`, `pathlib`,
> `asyncio`, `typing`, `logging`, `path`, `file`, `id`, `type`, `dict`,
> `list`, `set`, `tuple`, `str`, `int`, `bool`, `bytes`) — domain synonyms
> used where the prose would name such a word (`error_type`, `json_flag`,
> `path_str`). Deferred canonical ambiguities (SRS §7) are declared as
> `precondition=` in the Inputs cell; P3 must consult the ADR before binding
> those values. `state_mode` / `subprocess_mode` are declared per v2.13.0
> where a case exercises shared mutable state or spawns processes.
